# 旧车与新车双主线

## 有效主线

仓库后续只在以下两条部署主线上继续开发：

| 分支 | 用途 | 当前边界 |
| --- | --- | --- |
| `main-old-car` | 2026 旧车比赛、日常导航和回归修复 | 保持已实车验证的旧车定位、Nav2、任务、旧串口与可选双雷达障碍融合 |
| `main-new-car` | 2027 新车协议、动态云台定位、机构状态和狗洞能力 | 软件候选已合并；真实协议、外参、最终 CAD 和新车运动仍需实物验收 |

`main` 当前与 `main-old-car` 指向同一公共基线，仅作为 Gitee 默认分支和
历史兼容入口，不再直接承接新功能。设置好分支保护与默认分支后，可再决定
是否将默认入口切到 `main-old-car`；不要在此之前删除远程 `main`。

## 分支起点与已合并内容

两条主线共同起点为 `d735ee1`。该基线已经包含旧车现场整理、AMCL 高速
自转候选参数、启动入口以及双 MID360 障碍点云融合。

`main-new-car` 在公共基线之后按依赖顺序合入：

1. `26d5732`：操作手原始目标边界，默认关闭，不直接产生 Nav2 goal；
2. `4c21df0`：Competition V2 串口协议、参考 C codec 和无硬件链路；
3. `181fc6d`：底盘航向与 LIO 融合候选、动态云台状态和杆臂补偿；
4. `e58602f`：狗洞专用控制、扰动仿真和三维几何验证。

这些能力不反向合并到 `main-old-car`。真正与车型无关的修复应分别在两条
主线上验证后 cherry-pick，不能默认把整条新车主线合回旧车。

## 当前验收边界

### 旧车

- 现场导航、home、patrol、低血量回家及手动/自动操作流程已有实车证据；
- 双雷达障碍融合已完成静态遮挡验证，但右雷达外参和双雷达运动工况仍需实车验收；
- AMCL 高速自转后错误收敛仍是待办，当前候选参数不能视为根因修复；
- 当前地图可用于比赛准备，但建图脏点和 PGM/PCD 质量合同未完全闭环；
- pursuit、人工定位确认门和遥控器自动安全锁存按当前比赛安排后置。

### 新车

- Competition V2 codec、ROS 边界、姿态状态、心跳和失效逻辑已通过无硬件测试；
- 底盘航向/LIO 融合已通过数学与 fake runtime 测试，正式配置保持
  `initial_alignment_confirmed: false`；
- 狗洞中心线控制已通过参数化扰动和三维 Gazebo 穿越；
- 新下位机真实串口、航向符号/时间戳、云台零位、安装外参、最终 CAD、
  250 mm 净高裕量和新车实车运动均未验收。

## 后续开发规则

1. 旧车问题从 `main-old-car` 新建短期 `fix/old-car-*`；
2. 新车问题从 `main-new-car` 新建 `feature/new-car-*` 或 `fix/new-car-*`；
3. 每项能力独立构建、测试、合并，不在一个分支混合两个车型的未验收修改；
4. 合并提交继续使用简短中文说明；
5. 两条主线都应设置为保护分支，禁止 force-push；
6. 历史 feature/fix 分支在确认远程备份、默认分支和保护规则后再统一删除。

## 2026-09-01 旧车主线运行加固

以下三项经独立筛选和自动测试后允许进入 `main-old-car`：

- 语义区域的地图绑定兼容 `rm_map_tools` 生成的 UTC 时间戳 revision，同时继续拒绝路径
  穿越形式的标识符；
- readiness 只有在 Nav2 action 与 local/global costmap 都存在且仍有更新时才报告导航
  就绪；该状态仍是只读诊断，不撤销或授予底盘权限；
- 建图采样器、OctoMap 或 mapping session 任一退出时，标准建图入口整体退出，禁止以
  残缺进程图继续驾驶或保存。

高速自转自主恢复、自动坡道过滤、狗洞分段路由和 MPPI 高速探索仍保留在功能分支，待
各自实车通过门完成后再单独评估，不能随本轮运行加固一起合入。
